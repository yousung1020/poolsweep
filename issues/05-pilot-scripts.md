## 목표

스크립트 하나로 "환경 기동 → 실험 → 결과 저장"이 돌아가게 하고, 실행마다 필요한 기록을 자동으로 남긴다. 사람이 손으로 설정을 바꾸거나 기록하는 단계가 있으면 재현할 수 없고, 어떤 결과가 어떤 코드와 설정에서 나왔는지 추적할 수 없기 때문이다.

## 완료 기준

- 스크립트 하나로 설정 목록을 받아 기동, 부하, 저장, 종료까지 사람 개입 없이 돈다.
- 실행마다 아래 "이미 정해진 것"의 기록 항목이 결과와 함께 저장된다.
- 커밋되지 않은 변경이 있으면 스크립트가 실행을 거부한다.
- 실행 방법이 `CLAUDE.md` 6장과 `README.md`에 기록되어 있다.

## 작업 맥락

### 이미 정해진 것
- 실행마다 실행 ID, 커밋 해시, 전체 설정(처리 모델, 풀 크기, 쿼리 유형, 도착률 등), 버전(JDK, Spring Boot, 드라이버, 이미지 태그), Pi 온도와 스로틀링, `dropped_iterations`, `/ping` 기준선을 저장한다. (`CLAUDE.md` 3장, `RESEARCH.md` 6.8)
- 앱의 실제 적용 설정은 `/actuator/info`의 `experiment` 항목에서 읽을 수 있다. (#2, `CLAUDE.md` 6장)
- 설정당 5회 이상 반복하고, 실행 순서를 무작위로 섞고, 반복 사이에 쿨다운을 둔다. (`RESEARCH.md` 6.7)
- 결과 CSV에는 실행 ID, 설정 해시, 스로틀링 여부를 남긴다. (`RESEARCH.md` 6.8)
- 드롭이 0이 아니거나 스로틀링이 생긴 실행은 지우지 않고 무효 후보로 표시한다. (`CLAUDE.md` 3장, `RESEARCH.md` 6.5)
- 가상 스레드 핀닝은 JFR의 `jdk.VirtualThreadPinned` 이벤트로만 잰다. (`RESEARCH.md` 6.5, 10.1 (2))

### 지켜야 할 규칙
- 실험 전에는 변경 사항이 모두 커밋되어 있어야 한다. 커밋은 연구자에게 요청한다. (`CLAUDE.md` 3장, 7장)
- `results/`의 원자료는 수정하거나 삭제하지 않고, 재실행은 새 실행 ID로 추가한다. (`CLAUDE.md` 3장)
- 측정은 Pi와 맥북의 고정 환경에서만 한다. (`CLAUDE.md` 3장)
- 실행 기록의 형식은 `docs/WRITING.md` 5장을 따른다.

### 관련 파일과 명령
- #3의 k6 E1 스크립트와 #4의 Pi, 맥북 Compose를 호출한다.
- 실행 스크립트, `results/`, `LAB_NOTEBOOK.md`는 만들 예정이다.

- 확인 방법: 저장된 파일에 실행 ID, 커밋 해시, 설정 해시, 전체 설정, 버전, `/actuator/info`, 온도와 스로틀링, `dropped_iterations`, `/ping` 기준선이 모두 있다. 커밋되지 않은 변경이 있으면 스크립트가 실행을 거부한다. 같은 설정으로 다시 실행하면 기존 파일을 덮지 않고 새 실행 ID로 추가된다.
